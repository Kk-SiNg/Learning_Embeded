Declaration Patterns

Standard R/W Register

volatile uint32_t * const REG =
    (volatile uint32_t *)0xADDR;

Pointer locked. Data volatile. Most common.

Read-Only Register

volatile const uint32_t * const REG =
    (volatile const uint32_t *)0xADDR;

Pointer locked. Data read-only but hardware-updated.

ISR-Shared Flag

volatile uint8_t flag = 0;
// Set in ISR, checked in main

No pointer needed. Just volatile on the variable.

Flash Lookup Table

const uint16_t table[] = { 0, 100, 200 };
// Stored in Flash, not RAM

No volatile needed — value never changes.

Decision Flowchart

QuestionIf Yes →
Can hardware or an ISR change this value?Add volatile to the data type
Is the memory address fixed forever?Add const after the *
Should my code never write to this?Add const before the * (on the data type)

Right-to-Left Reading Rule

volatile uint32_t * const REG
         ↑              ↑       ↑
         │              │       └── REG is a ...
         │              └────────── constant pointer to ...
         └───────────────────────── a volatile uint32_t

Common Bugs

SymptomLikely CauseFix
Polling loop hangs at -O2 but works at -O0 Missing volatile on register/flag Add volatile
ISR flag never seen by main loop Compiler cached the flag value Declare flag as volatile
Register pointer accidentally reassigned Pointer is mutable Add * const
